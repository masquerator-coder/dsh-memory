# Agent 记忆系统最终设计方案

> 本方案综合了全部讨论，最终形态可概括为一句话：**五层架构为骨、被动锚点为脉、L2/L3 双层召回为脑、L4 项目级治理为手**——系统诚实于自身能力边界，把解析权交还 LLM，把晋升权交还用户。

---

## 第一部分 · 设计总纲

### 1.1 六条核心原则

| #    | 原则                           | 含义                                                         |
| ---- | ------------------------------ | ------------------------------------------------------------ |
| P1   | **原文不进入系统**             | LLM 只提交整理结果；原文留在 Harness 会话日志，系统仅存锚点指针 |
| P2   | **锚点被动捕获**               | 锚点由钩子自动附着，LLM 零感知；系统不解析、不验证锚点       |
| P3   | **诚实的能力边界**             | 系统不做它做不到的事（解析原文、自动验证锚点）；边界写进文档 |
| P4   | **衰减只降权，归档不删除**     | L2 注意力可衰减，事实必须留存；L4 退役不物理删除             |
| P5   | **写入时校验，检索时不再纠错** | L3 冲突在写入路径解决，不污染推理过程                        |
| P6   | **晋升决策权归用户**           | 系统只推荐，用户裁决；系统不自动晋升、不自动合并跨项目技能   |

### 1.2 关键决策清单

| 决策点     | 最终选择                                | 依据                        |
| ---------- | --------------------------------------- | --------------------------- |
| 锚点模式   | 增强型被动（钩子捕获 + 可选 ref_hint）  | Harness 不暴露原文 API      |
| L2 衰减    | Ebbinghaus + 访问增强 + 乘法融合        | 注意力管理，非事实管理      |
| L3 召回    | 快路径（<200ms）+ 慢路径（<2s，可迭代） | 即时回忆 vs 深度联想        |
| L4 触发    | 四级阶梯（显式/意图/信号/建议）         | 不靠 LLM 主动查询           |
| L4 生成    | 在线候选 → 离线成熟 → 审核发布          | 慢是美德                    |
| L4 作用域  | project 默认 / org / sys 分层           | 隔离污染，晋升收敛          |
| L4 晋升    | **用户决策**（系统推荐）                | 系统无法判断业务通用性      |
| L4 备份    | 全局备份仓库，不参与运行时匹配          | 防项目删除丢失 + 防重复创建 |
| 注意力预算 | 三级渐进披露，单轮技能 token ≤3300      | 防注意力分散                |

### 2.2 五层职责与接触矩阵

| 层                | 存储内容                       | 写入方                          | 召回方         | 生命周期              |
| ----------------- | ------------------------------ | ------------------------------- | -------------- | --------------------- |
| **L0** 锚点注册表 | 会话指针（session_id/seq/...） | 钩子自动捕获                    | 不参与召回     | 永久                  |
| **L1** 工作记忆   | 当前推理上下文                 | LLM 整理 + 召回注入             | 不查询（枢纽） | 会话级                |
| **L2** 情景记忆   | 带时间戳的事件                 | `memory_add` 主路径             | 高频召回       | 衰减 active→archived  |
| **L3** 语义记忆   | 实体-关系知识图谱              | `memory_add` 同步 + L2 异步抽象 | 语义+图推理    | 稳定，可修正留痕      |
| **L4** 程序记忆   | 版本化技能 SOP                 | 晋升流水线（用户决策）          | 匹配后加载执行 | Hot/Warm/Cold/Retired |

**Agent 接触面**：
- **写入面** = L1（工作台）+ L2（主写）+ L3（同步事实/关系）
- **召回面** = L2（经历）+ L3（知识）
- **执行面** = L4（技能匹配后加载）

## 第三部分 · L0 锚点注册表（被动捕获）

### 3.1 锚点结构

```python
anchor = {
  anchor_id: str,                    # 系统生成，如 an_7f3a2b

  # ---- Harness 钩子自动捕获（权威标识符）----
  session_id: str,                   # 必填
  message_id: str?,                  # 来自 UserPromptSubmit / assistant message
  turn: int?, step: int?, seq: int?, # 来自事件元数据，seq 全局单调递增（最强锚点）
  event_type: str,                   # SessionStart / UserPromptSubmit / ToolCall / ...
  timestamp: datetime,

  # ---- 可选语义提示 ----
  quote: str?,                       # LLM 抄录的短片段（≤200 字），系统不比对
  keywords: [str]?, speaker: str?,

  # ---- 异构 Agent 扩展 ----
  extra: dict?,                      # 私有定位信息，系统不解析

  # ---- 元数据 ----
  captured_by: "hook" | "llm" | "system",
  provided_fields: [str]
}
```

### 3.2 钩子映射

| Harness 钩子                 | 捕获内容                                                     |
| ---------------------------- | ------------------------------------------------------------ |
| `SessionStart`               | session 目录项 `{session_id, project_id, started_at}`        |
| `UserPromptSubmit`           | 用户消息锚点 `{session_id, message_id, turn, seq, timestamp}` |
| `PreToolUse` / `PostToolUse` | 工具调用锚点 `{session_id, seq, turn, step, tool_name}`      |
| `assistant/message`          | 助手消息锚点                                                 |

**关键机制**：LLM 调 `memory_add` 时，Harness 将其关联到一个 `seq`，插件在 `PreToolUse` 已捕获该上下文，**自动把当前 seq 及邻近事件作为默认锚点组**，LLM 无需提供任何定位字段。

### 3.3 系统能力边界（写进文档）

| 能力                        | 支持                         |
| --------------------------- | ---------------------------- |
| 存储 LLM/钩子提供的任意锚点 | ✅                            |
| 检索时原样透传锚点          | ✅                            |
| 自动验证锚点指向真实原文    | ❌（Harness 不暴露原文 API）  |
| 自动修复失效锚点            | ❌                            |
| 跨 Agent 统一溯源体验       | ❌（取决于各 Agent 会话存储） |

**解引用责任在 LLM / Agent UI**：UI 可消费锚点生成 `dsh-session://{session_id}/seq/{seq}#quote=...` 跳转链接。

### 3.4 被动反馈通道

```python
memory_anchor_feedback(anchor_id, status: "confirmed"|"stale"|"unresolvable", note?)
```

LLM 或 UI 在恰好比对到锚点内容时回传，系统记录 `last_feedback` 供后续展示。这是被动体系里唯一能积累"锚点真实有效性"信号的通道。

## 第四部分 · L2 情景记忆（含衰减）

### 4.1 数据模型

```sql
CREATE TABLE episodic_memory (
  memory_id     TEXT PRIMARY KEY,
  project_id    TEXT NOT NULL,          -- 项目作用域（L4 隔离的前提）
  summary       TEXT NOT NULL,
  summary_vec   VECTOR(1024),
  event_type    TEXT,
  participants  JSONB,
  outcome       TEXT,
  importance    FLOAT NOT NULL,
  stability     FLOAT NOT NULL,         -- S₀ × importance
  access_count  INTEGER DEFAULT 0,
  last_access   TIMESTAMPTZ,
  state         TEXT DEFAULT 'active',  -- active | dormant | archived
  anchor_ids    JSONB NOT NULL,         -- [{anchor_id, role: "primary"|"backup"}]
  created_at    TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_l2_vec   ON episodic_memory USING hnsw (summary_vec);
CREATE INDEX idx_l2_proj  ON episodic_memory (project_id, state);
CREATE INDEX idx_l2_time  ON episodic_memory (created_at);
```

### 4.2 衰减模型

```
稳定性 S = S₀ × importance × (1 + β · log(1 + access_count))    S₀=24h, β=0.5
保留度 R = exp(-Δt / S)                                          Δt = now - last_access
检索分 final_score = cosine_sim(query, summary) × (0.2 + 0.8 × R)
```

**状态转移（每日批处理）**：

| R 区间         | 状态     | 默认召回                      |
| -------------- | -------- | ----------------------------- |
| R ≥ 0.3        | active   | ✅                             |
| 0.05 ≤ R < 0.3 | dormant  | ❌（`include_dormant` 可召回） |
| R < 0.05       | archived | ❌（仅精确查询）               |

**铁律**：归档永不删除，锚点引用永久保留。

## 第五部分 · L3 语义记忆（知识图谱 + 双层召回）

### 5.1 图模型

**节点**：`Entity { id, name, type, aliases[], attributes{}, embedding, project_id }`

**边**：`Relation { head_id, relation, tail_id, confidence, valid_from, valid_to, recorded_at, source_episode_ids[], anchor_ids[], project_id }`

**双时态**：`valid_from/valid_to` 表达现实有效期，`recorded_at` 表达系统认知时点。

**关系类型注册表**：每种 `relation` 需注册 `{cardinality, domain, range}` 作为一致性校验元数据。

### 5.2 写入时一致性校验（四类规则）

| 规则     | 触发                              | 处理                                      |
| -------- | --------------------------------- | ----------------------------------------- |
| 基数约束 | functional 关系已有值又写入       | 按 `conflict_policy`                      |
| 类型约束 | head/tail 类型不在 domain/range   | 拒收该关系                                |
| 环检测   | 层级/因果类关系成环               | 拒收或标记 `cyclic_conflict`              |
| 证据冲突 | 同 (head, relation) 多个有效 tail | `last_write` / `evidence`(默认) / `defer` |

**冲突解决原则**：图谱中不存在"被删除的事实"，只有"已失效"（`valid_to` 设值）和"有争议"（`disputed`）。证据加权回查 `source_episode_ids` → L2 的新旧与强度。

### 5.3 双层召回

```
memory_search
      │
      ▼
查询路由器（轻量，<10ms）
  · 点查/属性问法      → 快路径 only
  · 关系连接词         → 快路径 + 扩散激活
  · 全局/聚合问法      → 快路径 + 社区摘要
  · 显式 mode="deep"   → 直接慢路径
      │
      ├──────────────┬──────────────┐
      ▼              ▼              
  快路径 Fast     慢路径 Deep
  <200ms          <2s（可迭代）
```

**快路径**：向量定位种子（5-10 个）→ 受限图扩展（深度 2-3 跳，边类型白名单）→ 路径打分（边置信度 × 1/√depth × 种子相似度）→ RRF 融合。热点子图缓存加速。

**慢路径**（三机制）：
- **扩散激活**：Personalized PageRank 从种子出发，软衰减召回"意想不到的关联"
- **迭代查询重写**：识别证据缺口 → 子查询 → 再检索，轮次 ≤4 且累计 token ≤预算
- **社区摘要上卷**：全局查询路由到层次化社区摘要（Leiden 检测）

**护栏**：遍历深度 ≤3 跳硬上限、边类型白名单、迭代双预算、超时自动降级为纯向量+RRF。

### 5.4 L2 与 L3 的关系

```
L2 事件 × N → 后台聚类抽象 → L3 事实/关系
                              └─ source_episode_ids → 指回 L2
L3 → L2 → L0 锚点 → 会话日志（三级溯源链，统一）
```

**四个关系维度**：
- **抽象**：L3 是 L2 的归纳产物，每条 L3 必须有 L2 证据支撑
- **溯源**：L3 → L2 → L0，统一引用链
- **检索**：并行召回 + RRF 融合；L3 给背景，L2 给当下
- **生命周期**：L2 衰减淡出，L3 稳定沉淀；L3 是 L2 的抗衰减记忆

**非对称铁律**：L2 只追加不改写，L3 可修正但留痕。L3 不自动写回 L2。

## 第六部分 · L4 程序记忆（项目级治理）

### 6.1 三级作用域

```
┌──────────────────────────────────────────────┐
│ sys 作用域（全局）  ← 平台预置 + 用户晋升到 sys │
├──────────────────────────────────────────────┤
│ org 作用域（组织）  ← 用户晋升到 org           │
├──────────────────────────────────────────────┤
│ project 作用域（默认）← 本项目 L2 轨迹归纳      │
└──────────────────────────────────────────────┘
```

**可见性规则**：`可见技能 = project:P ∪ org:O（若 P∈O）∪ sys`。其他项目技能完全不可见。

**优先级**：`project > org > sys`（作用域特异性优先）。高风险 sys 技能（`enforcement: hard`）不可被覆盖。

**注意力预算按项目独立计算**（项目 A 的 Hot 层不影响项目 B）。

### 6.2 触发机制（四级阶梯）

| 入口            | 时机                   | 机制                                                 |
| --------------- | ---------------------- | ---------------------------------------------------- |
| **1. 显式**     | Agent 主动             | `skill_match(task_context)` / `skill_load(skill_id)` |
| **2. 意图匹配** | `UserPromptSubmit`     | 轻量意图分类（规则+小模型，<50ms）→ 倒排索引查候选   |
| **3. 信号触发** | 运行时钩子             | 工具连续失败≥2、高风险工具调用前、敏感实体检测       |
| **4. 建议式**   | `memory_search` 返回时 | 结果中检测到技能相关信号，附带提示（不强制）         |

**匹配算法**（三级索引）：意图标签倒排（O(1)）→ 前置条件布尔过滤 → 语义排序（仅候选>1 时）。综合分 = `intent_match×0.4 + prereq×0.3 + semantic×0.2 + success_rate×0.1`。

**触发后行为**：
- **建议模式**（默认）：加载 Level 2 详情到 L1，LLM 自行决定
- **强制模式**（仅 `enforcement: hard`）：`PreToolUse` 拦截不符合约束的调用

### 6.3 生成时机（三段式）

```
在线产生候选（秒级）→ 离线判定成熟（天级）→ 审核发布（天级）
```

**来源**：L2 成功轨迹归纳（主力）/ L3 语义提炼 / 失败模式学习 / Agent 主动提议。

**成熟五条件**（全部满足）：
1. 同类成功 ≥3 次
2. 成功率 ≥80%
3. 跨 ≥2 个会话
4. 步骤一致率 ≥70%
5. 前置条件可识别

**发布流水线**：草稿生成 → 沙箱回放 → 风险分级审核 → Git 发布 → 成功率监控。**慢是 L4 生成的核心美德**。

### 6.4 规模治理（四层机制）

| 机制                   | 作用                                                         |
| ---------------------- | ------------------------------------------------------------ |
| **硬容量上限**         | 单项目 active ≤200、候选池 ≤50、全局 ≤2000；达上限强制退役评估 |
| **合并**               | sim>0.85 不生成新技能，改为扩展旧技能（参数化/分支/组合封装） |
| **分层 Hot/Warm/Cold** | Hot（近30天执行≥3次）常驻索引；Warm 按需；Cold 仅显式加载；**Hot 层硬上限 20 条** |
| **退役**               | 180天未用 / 近10次成功率<50% / 被高相似新技能取代 → `retired`，Git 保留可复活 |

### 6.5 注意力控制（三级渐进披露）

| Level           | 内容                                                      | 预算        | 注入位置        |
| --------------- | --------------------------------------------------------- | ----------- | --------------- |
| **1. 常驻索引** | Hot 层 ≤20 条，一行一条（skill_id + trigger + 15 字描述） | ≤500 token  | 系统提示词      |
| **2. 匹配详情** | top-1~2 完整 trigger/prereq/steps 概要                    | ≤800 token  | 按需注入 L1     |
| **3. 完整定义** | 含参数 schema、回退、示例                                 | ≤2000 token | `skill_load` 时 |

**单轮技能相关总预算 ≤3300 token**，硬约束，不可被技能数量突破。Hot 溢出时强制降级成功率最低者，而非扩大预算。

**写法规范**：描述 ≤15 字、trigger 2-4 个关键词且同类互斥、禁止在索引行出现步骤/参数。

### 6.6 命名空间隔离

```
sys:refund_v3      → 系统生成，全工具权限，全局可见
user:my_flow       → 用户编写，受限权限，仅所属用户/租户
ext:dify:xxx       → 外部导入，沙箱执行，按导入范围可见
```

**四类冲突检测**（`skill_load` 时执行）：触发重叠 / 步骤矛盾 / 依赖冲突 / 权限冲突。默认优先级 `sys > user > ext`，用户可配置覆盖（高风险 sys 技能除外）。

**跨命名空间不传递经验**：用户技能执行 100 次成功，也不会被系统学习晋升为 sys 技能。

### 6.7 备份仓库（Skill Archive）

```
┌─────────────────────────────────────────────────────────┐
│ 运行时技能库（Runtime Store）                             │
│   · 按作用域隔离：project / org / sys                    │
│   · 参与 skill_match 和 Level 1 注入                     │
└─────────────────────────────────────────────────────────┘
              ▲ 显式引用 / 用户晋升
              │
┌─────────────────────────────────────────────────────────┐
│ 备份仓库（Skill Archive）                                │
│   · 全局唯一，【不参与任何运行时匹配】                     │
│   · 只追加不删除；记录 origin_project                    │
│   · 入口：skill_archive_search（创建时）+ skill_import   │
│   · 是晋升推荐的原料池                                    │
└─────────────────────────────────────────────────────────┘
```

**硬规则**：备份仓库**永远不出现在 `skill_match` 候选集，也永远不出现在 Level 1 索引**。这守住了作用域隔离。

**状态**：`active / superseded / retired / orphaned（原项目已删除）`。

**创建时检索**：候选成熟后 → `skill_archive_search(trigger, step_summary)` → sim>0.85 走 `skill_import(mode="reference")`；0.6-0.85 标记 `similar_to` 由审核决策；<0.6 正常生成。

**三层存储**：Hot Archive（近90天活跃）<50ms / Warm Archive（90-365天）100-500ms / Cold Archive（>365天，对象存储）1-3s。

### 6.8 晋升机制（用户决策）

```
系统：发现相似簇 → 生成推荐（可解释的证据）→ 等待用户裁决
用户：同意 / 拒绝 / 稍后处理
系统：执行流转（不自动晋升）
```

**推荐触发**：跨项目相似簇（sim>0.85 且 ≥2 项目）/ 单项目高价值（成功率≥90% 且执行≥20次）/ 用户主动申请 / 月度全量扫描。

**推荐内容**：涉及技能列表 + 各技能指标 + 相似度分数 + 步骤一致率 + LLM 生成的自然语言推荐理由 + 建议的参数化方案。

**决策结果**：
- **同意** → 从备份库提出 → 参数化生成通用技能 → 写入 org/sys → 原项目技能标记 `promoted_to`（不删除）
- **拒绝** → 记录原因 → 同一簇 6 个月内不再推荐
- **稍后** → 保持 `pending`，进入待处理列表

**默认建议 org**；sys 级需平台管理员二次确认。

**护栏**：单用户每日 ≤5 条推荐、推荐过期 90 天不删、冷启动预置 sys 基础技能、通用技能成功率下降时通知晋升者并可一键回滚。

## 第七部分 · 写入路径（memory_add）

### 7.1 接口

```python
memory_add(
  summary: { text: str, importance: float },
  facts: [{ text, entities, confidence }]?,
  entities: [{ name, type, attributes }]?,
  relations: [{ head, relation, tail, confidence, valid_from }]?,
  event: { type, participants, outcome }?,
  ref_hint: { keywords?, time_range?, entity_hints?, quote? }?,   # 可选，关联历史锚点
  options: { dedup, conflict_policy } = {}
) → {
  accepted: { summary, facts, relations },
  rejected: [{ item, reason, detail }],
  ref_hint_matched: int,
  ref_hint_unmatched: int
}
```

**LLM 视角极简**：不需要知道锚点存在，只需在"确实记得"时给 `ref_hint`。

### 7.2 写入流水线

```
① 钩子自动捕获当前锚点（PreToolUse 上下文）
   → primary_anchor {session_id, seq, turn, step}
② ref_hint 关联历史锚点（可选）
   → 用 keywords + time_range + entity_hints 在锚点表检索 → backup_anchors[]
③ 整理结果校验
   → 去重（向量近邻 + hash）/ 冲突检测（仅图谱关系）/ 置信度分级
④ 分发写入
   → L0 锚点表 / L2 情景 + anchor_ids / L3 事实关系 + anchor_ids
⑤ 回执（不暴露锚点术语）
```

**关键**：L0 先写、无条件成功；部分成功语义（逐条回执，锚点失败不阻塞内容入库）。

## 第十部分 · 能力边界声明（写进产品文档）

### 10.1 系统能做的

- 存储并透传任意锚点信息（钩子自动 + LLM 可选提供）
- L2 情景记忆的衰减与归档（注意力管理）
- L3 知识图谱的多跳推理与写入时一致性校验
- L4 技能的项目级隔离、四级触发、规模治理
- L4 备份仓库的完整保留与创建时复用检索
- 晋升推荐（可解释、可追踪、用户决策）

### 10.2 系统不能做的

| 能力                     | 原因                       |
| ------------------------ | -------------------------- |
| 自动解析锚点指向真实原文 | Harness 不暴露原文读取 API |
| 自动修复失效锚点         | 同上                       |
| 主动验证整理结果的保真度 | 拿不到原文，只能间接观测   |
| 跨 Agent 统一溯源体验    | 取决于各 Agent 的会话存储  |
| 自动判断"技能是否通用"   | 业务边界问题，交用户决策   |
| 自动合并跨项目技能       | 同上，只推荐不执行         |

### 10.3 一句话总结

> **这套系统是 DeepSeek Harness 的"记忆与能力外科手术刀"**——它以五层架构组织记忆，以被动锚点诚实于原文边界，以 L2/L3 双层召回兼顾"找得到"与"想得深"，以项目级 L4 和用户决策晋升守住能力治理的谨慎底线。**它知道自己能切什么、不能切什么，把切不了的部分完整交还给最了解它的 LLM 和用户。**
